# คู่มือสาธิต TripPocket — 5–7 นาที

ก่อนนำเสนอ: เปิด APK ที่ build จาก main.dart ด้วยโหมด live, เช็กอินเทอร์เน็ต, เปิดแอปปลายทางที่รับข้อความได้ และสมัครบัญชี A/B สำหรับสาธิตเอง ไม่ใช้รหัสผ่านหรือข้อมูลส่วนตัวบนสไลด์

1. **0:00–0:45 ปัญหาและสมาชิก** — ข้อมูลเที่ยวกระจายอยู่หลายที่ เปิดหน้า login แล้วเข้าสู่ระบบบัญชี A ชี้ว่าข้อมูลแต่ละคนถูกแยกด้วย uid และ Rules
2. **0:45–1:45 สร้างทริป** — ชื่อ “เชียงใหม่ 3 วัน 2 คืน” จุดหมายเชียงใหม่ 6–8 พฤศจิกายน 2569 งบ 3,000 บาท ลองเงินติดลบหรือวันสิ้นสุดก่อนเริ่มให้เห็น validation ก่อนบันทึกค่าที่ถูก
3. **1:45–3:15 กิจกรรมและแผนที่** — เพิ่ม “คาเฟ่” วันแรก 09:00 ราคา 200 บาท แตะแผนที่และยืนยันหมุด เพิ่ม “อาหารกลางวัน” 12:00 ราคา 150 บาท กดยกเลิก picker เพื่อแสดงว่าหมุดเดิมไม่เปลี่ยน
4. **3:15–4:00 งบและ CRUD** — ยอดวางแผน 350 บาท คงเหลือ 2,650 บาท แก้ค่าอาหารเป็น 180 บาท → รวม 380 คงเหลือ 2,620 ลบรายการอาหารและตรวจยอดกลับเป็น 200 แสดงวันว่างได้
5. **4:00–4:45 เช็กลิสต์** — เพิ่มสายชาร์จ/บัตรประชาชน เช็กหนึ่งรายการ ปิดเปิดแอปใหม่ ให้เห็นว่า session และของยังอยู่ ชี้ว่าเช็กลิสต์อยู่เฉพาะเครื่อง ไม่ sync cloud
6. **4:45–5:30 แชร์** — เปิด preview ตรวจชื่อ วัน เวลา เงิน ไม่มี note/พิกัด/เช็กลิสต์ กดเลือกแอป ระบบให้ผู้ใช้เลือกเอง ยกเลิกได้ ไม่ต้องส่งข้อความหาใครระหว่างทดสอบ
7. **5:30–6:15 แยกบัญชี** — logout → login B แล้วไม่เห็นทริป A กลับ A ทริปเดิมยังอยู่
8. **6:15–7:00 อธิบายโครงสร้าง** — Riverpod streams → repository → Firebase SDK; ทริปมี activities subcollection เงินเป็น integer satang และรวมจากกิจกรรม ไม่เก็บยอดซ้ำ ลบทริปทำเครื่องหมาย deleting ก่อนลบลูก หากสะดุดกลับรายการแล้วลองต่อ

## อธิบายข้อจำกัดอย่างตรงไปตรงมา

- ทดสอบ Android Emulator กับมือถือจริงเป็นคนละหลักฐาน ดูไฟล์สถานะล่าสุดก่อนกล่าวว่าผ่านบนอุปกรณ์ใด
- งบเป็นประมาณการ ไม่ใช่การชำระเงิน ไม่คิดเวลาเดินทางหรือจัดเส้นทางอัตโนมัติ
- แผนที่ต้องใช้อินเทอร์เน็ต ส่วนเช็กลิสต์ใช้ในเครื่องได้
- ย่อช่วงวันตรวจจาก server และสมมติหนึ่งอุปกรณ์แก้ทริปในเวลาหนึ่ง ไม่รับประกัน concurrent edits
- Firebase project ใช้ Spark และมี quota ฟรี; ไม่มี custom server หรือ Go API
- ผลแชร์ไม่ยืนยันว่าผู้รับได้รับหรืออ่านข้อความ
