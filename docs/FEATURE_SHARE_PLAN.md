# แชร์แผนเที่ยวเป็นข้อความ

สถานะ 25 ตุลาคม 2569: มี formatter/preview/native service และ tests แล้ว native cancellation ผ่านบน Android Emulator แล้ว ส่วนแอปปลายทางยังต้องตรวจตาม IMPLEMENTATION_STATUS.md ฟีเจอร์นี้ส่งออกข้อความสรุปให้ผู้ใช้เลือกแอปและผู้รับเองผ่าน Android share sheet

## ผู้ใช้ทำอะไรได้

จากหน้ารายละเอียดทริป กด “แชร์แผนเที่ยว” → ดูตัวอย่างข้อความ → กด “เลือกแอปที่จะแชร์” → เลือกแอปและผู้รับ → ส่งผ่านแอปปลายทาง ยกเลิกที่ขั้นตอนไหนก็ได้โดยไม่เปลี่ยนข้อมูลทริป

ใช้ bottom sheet แสดงตัวอย่าง จึงยังคง 6 ประเภทหน้าจอเดิม ข้อความประกอบด้วยชื่อทริป จุดหมาย ช่วงวัน กิจกรรมแยกวันเรียงเวลา ค่าใช้จ่ายแต่ละกิจกรรม งบรวม ยอดวางแผน และเงินคงเหลือหรือเกินงบ ใช้ค่าที่บันทึกแล้วและโหลดครบในหน้า ไม่ใช้ draft ที่ยังไม่บันทึก

รุ่นแรกไม่ส่งออก note, เช็กลิสต์, พิกัด, uid หรือ document paths ไม่สร้างลิงก์สาธารณะหรือให้คนอื่นเข้าถึง Firestore การทำงานร่วมกันแก้ทริปหลายบัญชียังอยู่นอก MVP

## ตัวอย่างข้อความ

```text
TripPocket: เชียงใหม่ 3 วัน 2 คืน
จุดหมาย: เชียงใหม่
6–8 พฤศจิกายน 2569

7 พฤศจิกายน 2569
09:00 แวะคาเฟ่ — 200.00 บาท
12:00 อาหารกลางวัน — 150.00 บาท

8 พฤศจิกายน 2569
15:00 ซื้อของฝาก — 250.00 บาท

งบทั้งหมด: 3,000.00 บาท
ค่าใช้จ่ายที่วางแผน: 600.00 บาท
คงเหลือ: 2,400.00 บาท
```

วันที่ไม่มีรายการอาจละออกจากข้อความ ถ้ายังไม่มีกิจกรรมให้ระบุ “ยังไม่มีกิจกรรมในแผน” และยอดวางแผน 0 เมื่อโหลดข้อมูลสำเร็จแล้วเท่านั้น

## โครงสร้าง Frontend

```text
lib/features/sharing/
  domain/trip_share_formatter.dart
  data/platform_share_service.dart
  presentation/share_plan_sheet.dart
```

TripShareFormatter เป็น Dart function/class ที่รับ Trip และ Activities แล้วคืนข้อความแบบ deterministic ทดสอบโดยไม่เรียก native plugin ส่วน PlatformShareService ห่อ share_plus และส่งผลกลับให้ controller/UI

ใช้ share_plus รุ่นที่เข้ากับ Flutter/Android toolchain จริง ตรวจ requirements ก่อนเพิ่ม dependency ไม่ต้องเพิ่ม HTTP API, Cloud Function, Firebase Storage, collection หรือ field ในฐานข้อมูล

## สถานะและข้อผิดพลาด

- เปิดได้เมื่อทริป active และข้อมูลทริป/กิจกรรมโหลดสำเร็จ ไม่มี pending write; ปิดปุ่มขณะ preparing หรือเปิด share sheet
- ฟีเจอร์ใช้ข้อมูล snapshot ที่โหลดไว้ ถ้าเป็น cache ให้ระบุใน preview ว่าเป็นข้อมูลที่โหลดไว้ล่าสุด
- สร้างข้อความหนึ่งชุดสำหรับ preview และส่งชุดเดียวกัน หากข้อมูลอัปเดตระหว่างเปิด preview ให้ผู้ใช้เปิดตัวอย่างใหม่เพื่อใช้ข้อมูลล่าสุด
- เมื่อยกเลิก ไม่แสดงว่าส่งสำเร็จ และไม่เปลี่ยนข้อมูลใด ๆ
- หาก plugin/platform ระบุผลไม่ได้ ไม่อ้างว่าส่งถึงผู้รับแล้ว ผล share sheet ไม่ใช่หลักฐานการส่งถึงหรือการอ่าน
- หากแอปปลายทางไม่รับข้อความ ให้แจ้งข้อผิดพลาดและให้เลือกใหม่ โดยไม่ส่งอัตโนมัติหรือเลือกผู้รับแทนผู้ใช้

## เกณฑ์ตรวจรับ

- [x] ข้อความภาษาไทย วันที่ ลำดับกิจกรรม และจำนวนเงินตรงข้อมูลที่บันทึก
- [ ] เพิ่ม/แก้ไข/ลบกิจกรรมแล้วเปิด preview ใหม่ได้ข้อความล่าสุด
- [x] ทริปไม่มีกิจกรรม งบ 0 และเกินงบ แสดงผลถูกต้อง
- [x] Preview ไม่ใส่ note, packing, coordinates หรือ internal identifiers
- [x] ยกเลิก preview/share sheet แล้วข้อมูลคงเดิมและไม่อ้างว่าส่งสำเร็จ
- [ ] ทดสอบ native share sheet บน Android จริงอย่างน้อยหนึ่งแอปที่รับข้อความได้ โดยระบุแอปที่ทดสอบ
- [x] ไม่มีการเปลี่ยน Firestore Rules ให้บุคคลอื่นอ่านข้อมูลเพื่อรองรับการแชร์ข้อความ

## อ้างอิง

[share_plus](https://pub.dev/packages/share_plus) รองรับการส่งข้อความผ่าน share UI ของระบบ ผลและความเข้ากันได้ขึ้นกับแพลตฟอร์มและแอปปลายทาง ต้องทดสอบจริงก่อนอ้างว่ารองรับแอปใด
