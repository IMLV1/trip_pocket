# ส่วนขยาย TripPocket: แผนเที่ยวหลายจุดหมายในประเทศไทย

วันที่ 26 ตุลาคม 2569 สถานะ: ข้อเสนอออกแบบตามความต้องการใหม่ ยังไม่ใช่ฟีเจอร์ที่พัฒนา/ทดสอบแล้ว และยังไม่ได้เลือกหรือเปิดบริการ API แบบคิดเงิน

## ประสบการณ์ที่ต้องการ

เลือกจังหวัด วัน งบ จำนวนคน และรูปแบบเดินทาง → เลือกหมุดท่องเที่ยว/ร้านอาหาร/ที่พักหลายแห่ง → จัดลำดับรายวัน → เปรียบเทียบการเดินทางแต่ละช่วง → ดูงบและข้อเสนอปรับแผน → กดนำทางไปจุดถัดไป

ใช้ประเทศไทยเป็นขอบเขตข้อมูลสถานที่และเส้นทาง แต่ต้องแยกพื้นที่ที่มีข้อมูลขนส่งจริงออกจากพื้นที่ที่ยังไม่มีข้อมูล ไม่สัญญาค่าโดยสารและการต่อรถครบทุกจังหวัด

## สิ่งที่ต่อยอดจากโค้ดปัจจุบัน

กิจกรรมมี latitude/longitude, วัน เวลา และ estimatedCostSatang อยู่แล้ว หนึ่งทริปมีหลายกิจกรรม จึงใช้กิจกรรมเป็นจุดแวะต่อได้ แต่ปัจจุบันยังไม่มีแผนที่รวมหมุด การค้นหา/แนะนำสถานที่ เส้นทางถนน รายการต่อรถ หรือฐานราคาท่องเที่ยว

flutter_map แสดงแผนที่และหมุดได้ ไม่ได้ให้ข้อมูลเส้นทาง ค่าโดยสาร หรือระบบนำทางอัตโนมัติด้วยตัวเอง

## ฟีเจอร์ที่เสนอ

| ส่วน | พฤติกรรม |
|---|---|
| แผนที่รายวัน | หมุดมีเลข 1–N แยกประเภทเที่ยว/อาหาร/ที่พัก เลือกจากแผนที่หรือรายการ เพิ่ม ลบ สลับลำดับ และเปิดรายละเอียด |
| สถานที่แนะนำ | เลือกตามจังหวัด หมวด ความสนใจ งบ และระยะอ้อมเส้นทาง แสดงเหตุผล/แหล่งข้อมูล/วันที่ตรวจ ไม่ใช้คะแนน AI เป็นข้อเท็จจริง |
| เดินทางรายช่วง | A→B และ B→C เลือกรถยนต์ส่วนตัว มอเตอร์ไซค์ เดิน หรือขนส่งสาธารณะตามข้อมูลที่รองรับ ไม่บังคับยานพาหนะเดียวทั้งทริป |
| เปรียบเทียบตัวเลือก | แสดงเวลา ระยะทาง ราคาประเมิน จำนวนช่วงขึ้นรถ และจำนวนครั้งเปลี่ยนรถ แยกการเดินเท้าออกจากการขึ้นรถ |
| งบแยกประเภท | อาหาร ที่พัก ค่าเข้า เดินทาง น้ำมัน ทางด่วน ที่จอดรถ และอื่น ๆ พร้อมยอดต่อคน/รวมกลุ่ม หลีกเลี่ยงนับค่าเดียวสองครั้ง |
| ช่วยปรับแผน | เตือนเกินงบ แผนแน่น เดินทางอ้อม และเวลาเปิดปิดเมื่อมีข้อมูล เสนอทางเลือกพร้อมเหตุผลและผลต่างราคา/เวลา ผู้ใช้ยืนยันก่อนแก้แผน |
| นำทาง | ระยะแรกเปิด Google Maps ไปหมุดถัดไป ส่วนการวาดเส้นทางจริงในแอปต้องมี routing provider; เส้นตรงเชื่อมหมุดต้องติดป้ายว่าไม่ใช่เส้นทางถนน |

## ราคาและความน่าเชื่อถือ

- ทุกจำนวนเงินเก็บเป็นสตางค์ มี source, checkedAt และสถานะ userEntered / estimated / providerReported / unknown ตามแหล่งจริง
- ไม่มีข้อมูลต้องแสดง “ยังไม่ทราบราคา” ไม่ใช้ 0 บาทแทน และสรุปว่างบยังไม่รวมรายการใด
- รถส่วนตัว: ระยะทางถนน ÷ อัตราสิ้นเปลือง (กม./ลิตร) × ราคาน้ำมันที่ผู้ใช้ระบุ + ทางด่วน + ที่จอดรถ; ถ้าไม่มีระยะถนน ห้ามใช้ระยะเส้นตรงแทนโดยไม่ระบุ
- ที่พักระบุราคาต่อห้องต่อคืน จำนวนห้อง/คืน; อาหารต่อคนต่อมื้อ; ค่าเข้าต่อคน พร้อมประเภทผู้เข้าชมถ้าราคาต่างกัน
- ขนส่งสาธารณะเก็บเส้นทาง/สาย จุดขึ้นลง เวลาเดิน ระยะรอ และค่าโดยสารเฉพาะที่แหล่งข้อมูลให้; 3 ช่วงขึ้นรถมักหมายถึงเปลี่ยนรถ 2 ครั้ง ต้องตรวจกรณีรถสายเดิมวิ่งต่อไม่ต้องลงด้วย
- ตัวเลือกเส้นทางหลายจุดสำหรับขนส่งสาธารณะต้องคำนวณทีละช่วงตามเวลาออกเดินทางใหม่ ไม่ส่งทุกจุดเป็น transit request เดียว และไม่สรุปว่าแต่ละช่วงที่สั้นที่สุดจะทำให้ทั้งวันดีที่สุด

## แผนแบ่งช่วงที่แนะนำ

### V2.1 หลายหมุดและงบที่อธิบายได้

ใช้ Firebase Spark เดิม เก็บกิจกรรม/จุดแวะรายวัน เพิ่มหมวดและลำดับ แสดงแผนที่รวมหมุดและรายการค่าใช้จ่าย เพิ่มวิธีเดินทาง/ราคาที่ผู้ใช้กรอก เปิด Google Maps นำทางจุดถัดไปผ่าน Maps URL เตรียมสถานที่แนะนำที่คัดเองสำหรับจังหวัดนำร่องหนึ่งจังหวัด ระบุว่าครอบคลุมเฉพาะชุดข้อมูลที่มี

ช่วงนี้ยังไม่อ้างว่าคำนวณเส้นทางรถสาธารณะหรือค่าโดยสารอัตโนมัติ การเปิด Maps ภายนอกไม่ได้ส่งผลเส้นทาง/ราคากลับเข้า TripPocket

### V2.2 เส้นทางจริงและค้นหาสถานที่

เลือก provider โดยตรวจค่าใช้จ่าย สิทธิ์ใช้/จัดเก็บข้อมูล ความเข้ากันได้กับแผนที่ และทดสอบเส้นทางไทยจริงก่อน เลือกจังหวัดนำร่องและตัวอย่างที่ยืนยันได้ เพิ่มระยะถนน/เวลาและการเปรียบเทียบรถส่วนตัว ถ้ามี API secret ให้ใช้ตัวกลางที่ปลอดภัย ห้ามฝัง secret ใน Flutter ไม่เพิ่ม Go โดยอัตโนมัติ

Google Places ที่แสดงผลบนแผนที่ต้องใช้ Google Map ตามนโยบาย จึงไม่ควรวางข้อมูลจาก Places ทับ OSM เดิมโดยตรง หากเลือก Google ต้องประเมินการเปลี่ยนแผนที่และข้อกำหนดการเก็บข้อมูลด้วย

### V2.3 ขนส่งสาธารณะและข้อเสนอปรับแผน

เริ่มพื้นที่นำร่องที่ตรวจ coverage/สาย/ค่าโดยสารได้ เช่น พิจารณากรุงเทพฯ หลังทดสอบ provider ไม่ถือว่ารองรับล่วงหน้า แสดงสายรถและจุดเปลี่ยนต่อช่วง คำนวณราคาที่มีจริง แสดง unknown เมื่อขาดข้อมูล เพิ่มคำแนะนำด้วยกฎที่ตรวจสอบได้: งบ เวลา ระยะอ้อม และเวลาเปิดปิด ก่อนพิจารณา AI สำหรับการอธิบาย

## โครงสร้างที่เสนอ (ยังไม่ migrate)

- Activity เดิมเพิ่ม category, orderIndex, durationMinutes และ costItems ที่นิยามหน่วยราคา/จำนวนชัดเจน ต้องวาง schemaVersion และการอ่านข้อมูลเก่าก่อนเปลี่ยน Rules
- เพิ่ม transport legs ใต้ทริป อ้าง fromActivityId/toActivityId, mode, distanceMeters, durationSeconds, ค่าใช้จ่ายที่มีแหล่งกำกับ และรายละเอียดสาย/จุดขึ้นลงเท่าที่สัญญาผู้ให้บริการอนุญาต
- แก้/ลบ/สลับจุดหรือเวลาแล้วต้อง invalidate เส้นทางเดิม ลบกิจกรรมไม่ทิ้ง leg กำพร้า ลบทริปต้องล้าง legs ก่อน parent ตาม resumable deletion เดิม
- ยอดกิจกรรมและยอดเดินทางคำนวณแยกแล้วรวมครั้งเดียว ไม่บวก costItems ซ้ำกับ estimatedCostSatang ของข้อมูลเก่า
- PlaceRepository, RouteRepository, CostEstimator และ PlanSuggestionService แยกจาก widget เพื่อเปลี่ยนแหล่งข้อมูลและทดสอบได้
- Firestore ยัง scope ตาม uid และทดสอบสิทธิ์ข้ามบัญชี; หากใช้แค็ตตาล็อกสาธารณะต้องออกแบบสิทธิ์อ่าน/ผู้เขียนแยกชัดเจน

## เกณฑ์ก่อนเริ่มและตรวจรับ

เลือกจังหวัดนำร่องและแนวทางข้อมูลก่อน V2.2/V2.3 ไม่เปิด billing หรือ deploy บริการเพิ่มจากเอกสารนี้

- [ ] ข้อมูลทริปเดิมอ่านได้หลังขยาย schema โดยยอดเงินไม่เปลี่ยนผิด
- [ ] เพิ่ม/ลบ/เรียงหมุดแล้วรายการและแผนที่ตรงกัน แยกวันถูก
- [ ] จำกัดสถานที่ประเทศไทยด้วย country metadata/ขอบเขตจริงตามแหล่งที่เลือก ไม่ตรวจด้วยกรอบสี่เหลี่ยมอย่างเดียว
- [ ] ราคาไม่ทราบไม่กลายเป็นฟรี และไม่รวมยอดซ้ำ หน่วยต่อคน/ห้อง/คืนถูกต้อง
- [ ] เปลี่ยนหมุด/เวลา/ยานพาหนะแล้ว route เก่าถูกระบุว่าล้าสมัยหรือคำนวณใหม่
- [ ] provider ล่ม/ไม่มีรถ/ไม่มีราคา/เน็ตขาด แสดงสถานะจริงและแก้แผนต่อได้
- [ ] ทดสอบจำนวนสาย/จำนวนครั้งเปลี่ยนรถกับเส้นทางตัวอย่างจริงในพื้นที่ที่ประกาศรองรับ
- [ ] ทดสอบเปิด Maps และ fallback เมื่อไม่มีแอปติดตั้ง โดยไม่อ้างว่าแผนใน Maps ซิงก์กลับ
- [ ] คำแนะนำไม่แก้ข้อมูลโดยอัตโนมัติ และแสดงเหตุผล/สมมติฐาน
- [ ] Analysis, domain/widget tests, Rules tests เมื่อ schema เปลี่ยน และ Android integration ผ่านก่อนติ๊กเสร็จ

## แหล่งอ้างอิงที่ตรวจ 26 ตุลาคม 2569

- Maps URLs ไม่ต้องมี API key และเปิดแอปหรือ browser ได้: https://developers.google.com/maps/documentation/urls/get-started
- Transit routes ไม่รองรับ intermediate waypoints และมี fare เฉพาะเมื่อคำนวณครบทุก step: https://developers.google.com/maps/documentation/routes/transit-route
- Routes API ต้องเปิด billing และคิดตามการใช้งาน แยกจาก Firebase Spark: https://developers.google.com/maps/documentation/routes/usage-and-billing
- Places มีเงื่อนไขแสดงบน Google Map, attribution และการเก็บข้อมูล: https://developers.google.com/maps/documentation/places/web-service/policies

## เพิ่มตามคำขอ: ตำแหน่งปัจจุบัน — 26 ตุลาคม 2569

อ่าน GPS ครั้งเดียวเมื่อผู้ใช้กดปุ่ม แสดงจุดสีน้ำเงินพร้อมความแม่นยำและเวลาอ่านบนแผนที่ ปุ่มอัปเดตต้องกดเอง ไม่มี background tracking/stream หรือบันทึกตำแหน่งปัจจุบันลง Firestore/SharedPreferences ผู้ใช้ปฏิเสธสิทธิ์/ปิด Location/หมดเวลารอได้โดยยังวางแผนต่อได้

เพิ่ม geolocator จาก pub.dev และสิทธิ์ Android coarse/fine ขอตอนกดใช้งาน ไม่ขอ background location; เลือกตำแหน่งใกล้เคียงได้ บริการเป็น OS GPS ไม่ใช้ API key/บริการเสียเงิน

แยกปุ่มนำทางตามแผนจากหมุดก่อนหน้า กับนำทางจากฉัน (ไม่ระบุ origin ให้ Google Maps อ่านตำแหน่งเอง) Maps ภายนอกเป็นผู้แสดงเส้นทางถนน คำสั่งเลี้ยว/เสียงนำทาง ไม่รับผลกลับ ไม่มี turn-by-turn engine ใน TripPocket
