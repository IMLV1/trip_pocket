# ข้อเสนอโครงงาน TripPocket

## 1. ชื่อแอปพลิเคชัน
TripPocket — แอปพลิเคชันวางแผนการท่องเที่ยวส่วนตัว

## 2. ปัญหาและวัตถุประสงค์
ข้อมูลการวางแผนเที่ยวมักกระจายอยู่ในแชต โน้ต และแผนที่ ทำให้ติดตามแผนรายวันและประมาณค่าใช้จ่ายยาก TripPocket รวบรวมข้อมูลทริป สถานที่ กิจกรรม และงบประมาณไว้ด้วยกัน เพื่อช่วยให้ผู้ใช้เตรียมตัวและติดตามแผนการเดินทางได้สะดวก

## 3. กลุ่มผู้ใช้งาน
นักศึกษาและบุคคลทั่วไปที่วางแผนท่องเที่ยวด้วยตนเอง

## 4. ความสามารถหลักและขอบเขต MVP
- สมัครสมาชิก เข้าสู่ระบบ และออกจากระบบด้วยอีเมลและรหัสผ่าน
- เพิ่ม ดู แก้ไข และลบทริป ระบุชื่อ จุดหมาย วันเริ่ม วันสิ้นสุด และงบประมาณเป็นเงินบาท
- เพิ่ม ดู แก้ไข และลบกิจกรรมของทริป ระบุชื่อ วัน เวลา หมายเหตุ ค่าใช้จ่ายโดยประมาณ และพิกัดที่เลือกบนแผนที่
- แสดงกิจกรรมตามวัน เรียงตามเวลา โดยไม่คำนวณเวลาเดินทางอัตโนมัติ
- แสดงงบประมาณ ยอดค่าใช้จ่ายที่วางแผนไว้ และส่วนต่าง หากเกินงบให้แสดงยอดเกินอย่างชัดเจน
- เพิ่ม ลบ และทำเครื่องหมายเช็กลิสต์เตรียมของ เก็บในเครื่องโดยแยกตามบัญชีและทริป
- แชร์แผนเที่ยวเป็นข้อความจากหน้ารายละเอียด พร้อมตัวอย่างก่อนเปิด share sheet ให้ผู้ใช้เลือกแอปและผู้รับเอง
- ผู้ใช้เข้าถึงเฉพาะทริปของตนเอง โดยบังคับสิทธิ์ผ่าน Firestore Security Rules

ขอบเขตรุ่นแรกยังไม่รวมการจอง การชำระเงิน การแก้ไขทริปร่วมกันหลายบัญชี แชต ค้นหาสถานที่อัตโนมัติ จัดเส้นทางอัตโนมัติ และการแปลงสกุลเงิน รายละเอียดฟีเจอร์ใหม่อยู่ใน [แชร์แผนเที่ยวเป็นข้อความ](FEATURE_SHARE_PLAN.md)

## 5. หน้าจอและ Screen Flow
1. เข้าสู่ระบบ
2. สมัครสมาชิก
3. ทริปของฉัน พร้อมเมนูออกจากระบบ
4. สร้าง/แก้ไขทริป
5. รายละเอียดทริป: แผนรายวัน สรุปงบ และเช็กลิสต์
6. เพิ่ม/แก้ไขกิจกรรม พร้อมแผนที่เลือกพิกัด

กระบวนการหลัก: เข้าสู่ระบบ → สร้างทริป → เพิ่มกิจกรรมและเลือกหมุด → บันทึก → ดูแผนรายวันและงบรวม → แก้ไขหรือลบกิจกรรม

## 6. เทคโนโลยีที่วางแผนใช้
Frontend ใช้ Flutter และ Backend ใช้ Firebase ผ่าน SDK โดยตรง จึงไม่ต้องพัฒนา Go server เพิ่ม

| ส่วนประกอบ | เทคโนโลยี / หน้าที่ |
|---|---|
| แอปมือถือ | Flutter / Dart โดยเริ่มทดสอบบน Android |
| ระบบสมาชิก | Firebase Authentication |
| ฐานข้อมูล | Cloud Firestore |
| แผนที่ | flutter_map / latlong2 สำหรับเลือกหมุด โดยเลือก tile provider ตามเงื่อนไขก่อนใช้งานจริง |
| ข้อมูลในเครื่อง | SharedPreferences สำหรับเช็กลิสต์ขนาดเล็ก |
| แชร์แผนเที่ยว | share_plus สำหรับเปิด share sheet ของระบบ |

Mobile / External Features ที่เลือกคือแผนที่ Local Storage และการแชร์ข้อความผ่านระบบ ส่วนการอ่าน/บันทึก Firestore และการโหลดค่าตั้งค่าเป็น Asynchronous Operations

## 7. โครงสร้างข้อมูลเบื้องต้น
แบบฐานข้อมูลฉบับละเอียด: [Database Design](DATABASE_DESIGN.md)

- users/{uid}/trips/{tripId}: title, destination, startDate, endDate, budgetSatang, status, createdAt, updatedAt
- users/{uid}/trips/{tripId}/activities/{activityId}: title, date, timeMinutes, estimatedCostSatang, latitude, longitude, note, createdAt, updatedAt
- เช็กลิสต์ในเครื่อง: แยกคีย์ตาม uid และ tripId แต่ละรายการมี id, text และ checked

เก็บจำนวนเงินเป็นจำนวนเต็มหน่วยสตางค์ วันที่เป็น YYYY-MM-DD และเวลาเป็นนาทีตั้งแต่เที่ยงคืน รุ่นแรกใช้เวลา ณ จุดหมายตามที่ผู้ใช้กรอกและไม่แปลงเขตเวลาอัตโนมัติ การลบทริปใช้สถานะ deleting เพื่อหยุดการแก้ไข แล้วลบกิจกรรมลูกก่อนลบ parent และเช็กลิสต์ หากสะดุดให้ลองต่อได้ รายละเอียดสัญญาข้อมูลอยู่ใน [Backend Architecture](BACKEND_ARCHITECTURE.md)

## 8. Validation และสถานะระบบ
- ตรวจรูปแบบอีเมล รหัสผ่าน และยืนยันรหัสผ่านตามข้อกำหนด Authentication
- ชื่อทริป จุดหมาย และชื่อกิจกรรมห้ามว่าง
- วันสิ้นสุดทริปต้องไม่ก่อนวันเริ่มต้น
- วันกิจกรรมต้องอยู่ในช่วงวันที่ของทริป
- งบและค่าใช้จ่ายต้องเป็นตัวเลขไม่ติดลบ
- กิจกรรมต้องมีพิกัดที่เลือกก่อนบันทึก
- หากย่อช่วงวันของทริปจนมีกิจกรรมอยู่นอกช่วง ให้แจ้งผู้ใช้ปรับกิจกรรมก่อนบันทึก
- แสดงสถานะกำลังโหลด ไม่มีข้อมูล และข้อผิดพลาด พร้อมให้ลองใหม่
- ขอให้ยืนยันก่อนลบข้อมูล และป้องกันการกดบันทึกซ้ำขณะบันทึก

## 10. ตัวอย่างสาธิตและเกณฑ์สำเร็จ
สร้างทริปเชียงใหม่ 3 วัน 2 คืน งบ 3,000 บาท → เพิ่มกิจกรรมสองรายการพร้อมหมุดและค่าใช้จ่าย → ตรวจยอดรวม → แก้ไขกิจกรรมและตรวจว่ายอดเปลี่ยน → ลบกิจกรรม → เพิ่มและเช็กของเตรียมเดินทาง → ปิดเปิดแอปเพื่อตรวจข้อมูล → ออกจากระบบและตรวจว่าบัญชีอื่นเข้าถึงทริปนี้ไม่ได้

ถือว่า MVP พร้อมเมื่อกระบวนการดังกล่าวทำงานบนอุปกรณ์จริง ฟอร์มปฏิเสธข้อมูลผิด จัดการข้อผิดพลาดได้ และผู้พัฒนาสามารถอธิบายโครงสร้างข้อมูล กฎสิทธิ์ และการทำงานแบบ asynchronous ได้
